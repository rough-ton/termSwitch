# Contributing

## Commit, PR and issue standards

- **No tool-generated attribution, ever.** That means:
  - no "Generated by" or "Generated with" footers
  - no `Co-authored-by` trailers for tools
  - no session links
  - no similar text in commit messages, PR descriptions, issues, code, comments or docs
- CI enforces this with `tools/check_attribution.py`, which scans every commit and all
  tracked files.
- Enable the same check locally, so a bad commit message is rejected before it's made:

  ```bash
  git config core.hooksPath .githooks
  ```

- Commit messages: a short imperative subject (under 72 characters), a blank line, then
  what changed and why. Reference issues with `#n`, and use `Closes #n` in the commit or
  PR that finishes an issue.

## Branches

- Work on a branch, then open a PR into `main`. Every merge publishes a release.
- When a PR is closed, merged or not, its branch is deleted automatically by
  `.github/workflows/branch-cleanup.yml`. Branches with no PR yet, or with another open
  PR, are kept.
- A deleted branch can be restored from its PR page ("Restore branch").

## Development

```bash
python -m pip install --require-hashes -r requirements.lock -r requirements-dev.lock
python -m pytest -q
python tools/check_attribution.py --commits --files
```

Dependency changes go in the `.in` files; regenerate the locks as described in [docs/development.md](docs/development.md#dependency-locks).
When a dependency is added or its locked version changes, update the summary table in
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) and add its license text. CI fails
until every package in `requirements.lock` is listed with the locked version.
